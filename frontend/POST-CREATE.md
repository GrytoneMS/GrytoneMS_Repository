## API·인증·명세 대조

브랜치 기준 커밋은 `1a98c52`입니다. 이후 fetch로 확인한 `origin/dev` `04717fa`도 작성 DTO·서비스 검증·인증 코드는 동일합니다. 새 원격 변경을 작업 브랜치에 가져오지는 않았습니다.
`C:/Users/user/Documents/카카오톡 받은 파일/그려톤_API 명세서 (1차).pdf`의 공통 규칙(2~3쪽), 작성(7~8쪽), 코드값(11쪽)을 확인했습니다.
백엔드 `PostCreateRequest`, `PostService.validate`, `PostController`, `SecurityConfig`, `PostApiTest`와 S07도 대조했습니다.

- 인증 연결 후 기존 `apiRequest`로 `POST /api/posts`를 호출하도록 API·제출 함수를 준비했습니다. 정상 계약은 HTTP 201, `{ success: true, data: { id: number } }`이며 검증한 id의 `/posts/{id}`로 이동합니다. 현재 화면에는 토큰 공급 경로가 없어 이 요청을 보내지 않습니다.
- 제목 5~40자, 소개 20~1,000자, 역할 1~5개, 역할명 1~30자, 인원 정수 1~5명, 선택 요구 조건 최대 100자입니다.
- 대면·혼합은 장소와 모임 빈도(최대 30자)가 필수입니다. 캠퍼스·직접 입력은 상세 장소(최대 100자)가 필수입니다.
- 온라인으로 바꾸면 장소·빈도는 전송 시 null이 됩니다. 입력 상태는 보존해 다시 선택하면 복구됩니다.
- 공모전·대회는 행사명·주최(각 최대 100자), 공식 링크(최대 500자), 접수 마감일이 필수입니다. 다른 유형은 event를 null로 전송합니다.
- 연락 링크는 필수이며 최대 500자입니다. 요구 조건이 비어 있으면 null로 전송하며 안내 문구를 요청 데이터에 넣지 않습니다.
- 날짜: 마감일은 **오늘 포함 이후**, 마감일 ≤ 활동 시작일 ≤ 종료일입니다. Figma의 ‘오늘 이후’ 표기를 현재 백엔드의 `isBefore(today)` 검사에 맞춰 명시했습니다. 프론트 날짜는 KST, 백엔드 기본 시간대도 Asia/Seoul입니다.
- 행사 접수 마감일은 현재 백엔드가 필수 여부만 검사하므로 추가 날짜 순서 규칙을 만들지 않았습니다.
- 링크는 URL 입력 의미에 맞춰 http/https 형식을 검사합니다. 현재 백엔드 DTO는 링크의 필수·길이만 검사하며 URL 형식 검사는 없습니다. 이 차이는 서버 계약 변경 없이 프론트 입력 검증으로만 존재합니다.
- 백엔드는 JWT Bearer + 학교 인증 회원 권한을 사용합니다. `X-User-Id` 임시 인증은 없습니다.
- **현재 차단 동작:** 공통 인증 컨텍스트·토큰 공급 경로가 없습니다. 별도 인증 체계·토큰 저장·사용자 ID 하드코딩은 추가하지 않았습니다. 유효 폼도 토큰 없이 실제 등록할 수 없고, API 함수를 직접 호출해도 토큰이 없거나 공백이면 `fetch` 전에 차단합니다. 이 검사는 토큰 존재 여부만 검사하며 JWT 유효성·학교 인증 권한은 서버의 역할입니다.
- 개발용 상시 안내는 `CreateIntegrationNotice.tsx`, 요청 차단 안내와 오류는 `create-integration.ts`로 분리했습니다. 인증 연결 후 안내 컴포넌트와 호출부를 제거하고 공통 토큰을 제출 함수의 요청별 옵션에 전달합니다. 토큰 없는 요청 방어는 최종 인증 흐름에 맞춰 유지·조정할 사항입니다.
- 401/미인증 오류의 새 탭 링크는 제거했습니다. 현재는 오류 안내만 하며, 로그인·학교 인증 이동 방식은 확정하지 않았습니다. 아래 협의 사항을 먼저 맞춰야 합니다.
- 필드 오류 배열 및 Record 형식, 중첩 `roles[0].roleName`·`event.name` 필드 오류를 표시합니다. 일반 오류·정지·등록 제한도 표시하며 입력은 초기화하지 않습니다.
- 전송 중에는 입력과 등록 버튼을 잠그고, 재렌더 전의 중복 제출도 차단합니다. 페이지 이탈 시 요청을 취소하고 늦은 결과를 무시합니다. 취소가 서버 저장까지 취소한다는 보장은 없습니다.

PR #17은 미병합 상태라 이 브랜치에 가져오지 않았습니다. 현재 dev 상세의 null 요구 조건 표시 수정은 별도 PR #17 범위입니다.
backend·인증·프로필·내 모집글·내 지원 내역 파일은 수정하지 않았습니다.

## 연희님 및 백엔드 담당자와 협의할 사항

- PDF는 401 → 로그인 화면, UNVERIFIED → 학교 인증 안내 화면 이동을 명시합니다. 연희님과 공통 인증 컨텍스트 사용법, 이동 경로·복귀 경로, 입력 보존 수명과 방식을 맞춰야 합니다. 이전 새 탭 링크는 최종 방식이 아니며 현재 제거했습니다. 이번 작업에서는 실제 메시지를 보내지 않았습니다.
- 현재 입력 보존은 작성 화면의 React 상태 안에서만 동작합니다. 검증·등록 차단·요청 실패 시 초기화하지 않습니다. 새로고침이나 다른 화면 이동 이후의 복원은 구현하지 않았으며, 임시저장이나 별도 저장 체계를 만들지 않았습니다.
- http/https만 허용하는 프론트 URL 검증은 PDF에 명시되지 않았고 백엔드에도 없습니다. 허용 프로토콜·URL 형식과 서버 검증 범위를 합의해야 합니다. 이번에는 기존 추가 규칙을 임의로 변경하지 않았습니다.
- 모임 빈도 30자, 행사명·주최 각 100자, 공식 링크 500자는 최신 백엔드에 있지만 PDF에는 세부 길이가 없습니다. 현재 프론트는 최신 백엔드 제한을 사용하며 명세 보완 여부를 확인해야 합니다.
- PDF의 ‘오늘 이후’는 코드에서 오늘을 포함합니다. 오늘 마감 허용 문구를 명확히 할 사항입니다. 행사 접수 마감일 순서 제한은 현재 명세·서버에 없어 추가하지 않았습니다.

## 검증

```powershell
npm.cmd run build
npm.cmd run lint
node scripts/check-post-create.mjs
node scripts/check-posts.mjs
```

- 작성 자동 검증 14개: 필수·길이 경계·날짜·인원·조건부 입력, 요청 JSON, 선택 요구 조건, 원본 보존, 반환 id, 필드 오류, 권한·등록 제한 오류, 잘못된 응답·HTTP/네트워크 실패, 중복 제출, 성공 이동 콜백, 실패 후 재시도, 이탈 취소, 토큰 없음·빈 값·공백의 fetch 0회 및 입력 유지.
- 실제 전송·성공·실패 경로 검증은 테스트 코드 안에서만 명시적으로 테스트 토큰을 전달하고 fetch를 가로챕니다. 화면에 테스트 토큰을 넣거나 개발용 등록 우회 기능을 제공하지 않습니다.
- 기존 목록·상세 검증 10개: 작성 라우트를 실제 폼으로 변경한 부분 외에 기존 검증을 유지합니다. 인증·프로필 등 기존 경로의 정적 렌더를 포함합니다.
- 위 검증은 Vite SSR 모듈과 가로챈 fetch 응답을 사용합니다. 실제 브라우저 제출·화면 이동·레이아웃·JWT·CORS·서버 저장을 검증한 것은 아닙니다.
- 실제 서버: localhost:8080 `/api/schools` 연결 실패. 생성 API의 실제 인증·저장·성공 응답은 미검증입니다.
- 사용자 브라우저 확인: 작성 화면과 입력 조건 검증이 정상 동작함을 사용자가 확인했습니다. 실제 등록 성공은 확인하지 않았습니다.
- 에이전트 브라우저 제어는 현재 URL을 확인하지 못해 중단됐습니다. 사용자 확인과 별개로, 특정 화면 폭별 레이아웃·키보드 접근성 전체 항목을 확인했다고 주장하지 않습니다.
