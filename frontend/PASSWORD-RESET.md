# 비밀번호 재설정 (AUTH-05)

- 시작 시 작업 트리 깨끗함. fetch한 최신 origin/dev `4928c06`에서 `feature/front-AUTH-05` 생성. 기존 NOTI-03 브랜치와 stash 3개 보존.
- #50은 OPEN/미병합으로 확인. 설정 파일은 가져오거나 복제하지 않음. 병합 후 `SettingsPage.tsx` 계정 관리의 비밀번호 재설정 준비 항목을 `/forgot-password` Link로 교체하면 됨.
- Controller·PasswordResetRequest·PasswordResetConfirmRequest·AccountService·SecurityConfig·JwtAuthenticationFilter·메일 발송 구현을 대조함. backend 변경 없음.

## 계약과 동작

- POST `/api/auth/password-reset`: `{ email }`. 공백 제거 후 전송. 성공 응답에만 가입 여부를 드러내지 않는 동일 안내 표시. 네트워크·메일 발송·서버 오류는 실패로 안내하고 재시도 허용.
- POST `/api/auth/password-reset/confirm`: `{ token, newPassword }`. 영문과 숫자를 포함한 8~64자, 확인값 일치 검사. 확인값은 서버로 보내지 않음.
- 서버 링크는 30분·일회용. `PASSWORD_RESET_TOKEN_INVALID`는 만료/이미 사용됨을 함께 안내하고 재요청 링크 제공. 토큰 누락 시 입력 폼 대신 재요청 안내.
- 동일 tick 중복 제출 차단, 처리 중 입력 잠금, 이탈 시 취소와 늦은 응답 무시. 성공 시 비밀번호 입력 및 메모리 토큰 제거, 로그인 링크 제공. 실패 결과가 불확실하면 재요청 가능.
- 공개 API에는 Bearer·쿠키를 보내지 않음. 서버는 비밀번호 변경으로 기존 JWT를 폐기하지 않으며 프론트도 기존 세션을 임의로 변경하지 않음. 자동 로그인이나 전체 기기 로그아웃을 구현했다고 간주하지 않음.
- 토큰·비밀번호를 스토리지·로그·문서에 기록하지 않음. 토큰을 DOM에 표시하거나 hidden input으로 만들지 않음. 진입 후 현재 history URL의 query를 제거하고 메모리에서만 사용하므로 새로고침하면 메일 링크를 다시 열어야 함. 문서의 no-referrer 정책과 API 요청별 no-referrer를 적용. 최초 메일 링크 URL을 받는 호스팅 서버의 접근 로그 정책은 운영 측 확인 필요.

## 실행과 수동 확인

사용자가 비밀번호 재설정 화면을 직접 확인했고 문제없다고 확인함. 아래 세부 체크리스트를 각각 확인했다는 의미로 확대하지 않으며, 실제 API·메일 수신·유효한 링크를 통한 재설정 성공은 미검증.

`cd frontend`에서 `npm.cmd run dev` 실행 후 터미널 주소 사용(기본 `http://localhost:5173`). 환경 파일은 변경하지 않음.

1. `/login`에서 비밀번호 재설정 링크 → `/forgot-password`. 로그아웃 상태에서도 접근. 잘못된 이메일 오류, 정상 요청 안내, offline/서버 실패 후 재시도 확인.
2. 실제 메일 환경에서 별도로 승인된 전용 테스트 계정으로만 요청하고 받은 링크를 열기. 기존 팀장·지원자·관리자 계정은 사용하지 않기. 실제 재설정 토큰은 공유·캡처·문서 기록하지 않기.
3. `/reset-password` 직접 접근 시 누락 안내와 재요청 링크 확인. 메일 링크에서는 짧은 비밀번호/영문 또는 숫자 누락/65자 초과/확인 불일치 검증. 처리 중 연속 클릭과 Enter 입력 차단 확인.
4. 전용 계정으로 성공 후 비밀번호 폼 제거와 로그인 이동, 새 비밀번호 로그인 확인. 만료·재사용 링크에서 재요청 확인. URL에서 query 제거와 새로고침 시 재요청 안내 확인.
5. PC/모바일 폭의 넘침, Tab·Shift+Tab 포커스, Enter 제출, 오류/성공 안내 확인.

## 검증 범위

- 자동: build·lint, `check-password-reset.mjs` 8개, 공통 인증 16개, 모집글 12개와 `git diff --check` 통과. 요청 계약·검증·중복 잠금·실패/재시도·토큰 오류·취소·공개 정적 렌더 검사. API를 가로챈 검사이며 실제 서버/메일/브라우저 검증과 구분.
- 실제 API: 실행하지 않음. 계정 비밀번호 변경 없음.
- 메일 수신: 미검증. 서버는 SMTP 미설정 시 본문을 로그로 대체하므로 API 200만으로 실제 메일 수신을 확인할 수 없음. 운영 설정 변경 없음.
- 사용자 수동 확인: 비밀번호 재설정 화면을 직접 확인했고 문제없음. 구체적인 PC/모바일 폭·키보드·URL 정리·실제 성공 후 입력 제거 및 로그인 흐름의 개별 확인 여부는 미검증으로 유지.
- 최종 정리 시 fetch 후 origin/dev `4928c06`과 HEAD 동일함을 확인. 추가 병합과 충돌 없음. #50은 여전히 OPEN이므로 설정 연결은 후속 작업으로 유지.
- 관련 파일만 커밋·일반 푸시하고 dev 대상 PR을 생성하는 범위. 원격 병합·회원 탈퇴·알림함·backend·환경 파일 변경 없음. 기존 테스트 계정 비밀번호 변경 없음.
