# 모집·지원 실제 인증 연결 (AUTH-04)

## 최종 검증 상태 (2026-11-17)

- 아래 초기 구현 단계의 검증 기록과 별도로, 로컬 MySQL·Redis·백엔드에서 mock·개발 예시를 끄고 실제 API 검증을 완료했습니다. 로컬 DB 준비는 Git 밖에서 수행했으며 이 변경에 백엔드 코드·DDL·백업·테스트 계정 정보·환경 파일·로그를 포함하지 않습니다.
- 실제 API 통과: 비로그인 공개 목록/보호 API 차단, 팀장 작성·수정·내 모집글, 스크랩 등록·조회·해제, 지원·지원자 조회·수락, 수락자 내 지원/연락처, 별도 사례의 취소·팀 나가기·내보내기, 모집 마감·지원자 없는 글 삭제, 일반 사용자 관리자 접근 거절/관리자 조회.
- 서버 정책도 확인했습니다: 취소 후 재지원은 409 ALREADY_APPLIED, 정원 충족 시 역할/글 마감, 팀에서 나간 사용자의 연락처 접근 거절. 재개 시 기존 데이터를 재사용해 로그인·CORS·권한·보존된 사례 상태·개인 목록 격리를 다시 확인했습니다. 변경 API를 중복 실행하지 않았습니다.
- 사용자가 브라우저에서 직접 확인한 항목: `/posts`의 작은 테두리형 로그아웃 버튼 배치. 이 확인을 로그아웃 기능이나 다른 화면 전체의 통과로 확대하지 않습니다.
- 브라우저 미검증: 화면을 통한 전체 모집/지원 흐름, 로그아웃·계정 전환 후 이전 개인정보/모달 제거, 좁은 화면 줄바꿈, 실제 화면의 401/403·네트워크 중단·응답 유실/재조회 실패. 자동 브라우저 연결은 `The browser access host is unavailable`로 사용할 수 없었습니다. API 검증과 정적 렌더/회귀 검증은 브라우저 검증과 구분합니다.
- 로그아웃 스타일은 로그인 상태 영역에만 적용합니다. 세로 중앙 정렬·12px 간격·줄바꿈을 지원하고 공통 버튼 및 기존 토큰 제거/계정 데이터 정리 로직을 유지합니다.

이하 내용은 초기 구현과 당시 검증 범위의 기록입니다. 최종 통합 검증 상태는 위 내용을 기준으로 합니다.

## 기준·범위

- 보존 커밋 `4bf40a0`에서 AUTH-04 작업을 재개했습니다. 최종 원격 조회 기준 `origin/dev=0671aaa`이며 #43·#44·#45 모두 MERGED입니다. 작업 중 #45 병합을 확인해 최신 dev로 로컬 병합을 다시 진행했습니다.
- 최신 dev를 로컬 병합하고 App·목록·상세 충돌을 해결했습니다. 충돌 해결에 공통 인증 연결이 함께 들어 있어 전체 검증된 결과를 로컬 병합 커밋으로 보존합니다. 미병합 PR은 가져오지 않았습니다. #46 백엔드 변경도 최신 dev에 이미 병합된 상위 변경이며 직접 수정하지 않았습니다.
- 기존 stash 3개·APPL-09 백업·보존 커밋을 유지합니다. 로고·backend·DB·계정은 직접 수정하지 않으며 환경 파일·로그·임시 파일은 커밋하지 않습니다. 푸시·PR 생성·원격 병합은 하지 않습니다.

## 공통 세션

- 기존 `readAccessToken`의 sessionStorage 우선·localStorage 차선 정책과 기존 키를 그대로 사용합니다. 토큰을 새 위치에 저장하지 않습니다.
- 기존 로그인 저장 함수에 변경 알림을 추가했습니다. 로그아웃은 기존 두 저장소의 해당 키만 제거합니다. 서버 토큰 재발급·강제 폐기 API를 만들지 않았습니다. 로그아웃은 로컬 세션 종료이며 이미 발급된 JWT의 서버 유효기간 정책은 바꾸지 않습니다.
- `GET /api/users/me`의 실제 id·status·role을 검사한 뒤 session을 공급합니다. 토큰 존재만으로 로그인 확인 완료·학교 인증·ADMIN을 추정하지 않습니다.
- 확인 중/checking, 비로그인/anonymous, 로그인/authenticated, 조회 실패/error를 구분합니다. 401은 세션 만료, 403은 권한 오류, 네트워크/응답 오류는 조회 실패로 안내합니다. 재발급·자동 재전송·자동 화면 이동 반복은 없습니다.
- 보호 요청은 확인된 session의 token/userId를 사용합니다. 작성·지원은 실제 VERIFIED 상태도 확인하며 서버의 최종 권한 검사는 그대로 유지합니다.
- storage 이벤트·로그인/로그아웃 알림·focus·저장소 동기화로 변경을 감지합니다. 학교 인증·초기 프로필 화면을 떠날 때 상태를 재조회합니다. 동일 토큰에서도 실제 사용자 ID가 달라지면 화면 세대를 교체합니다.
- 계정 변경·로그아웃 시 기존 화면을 다시 마운트하고 개인 목록·연락처·확인창을 폐기합니다. 세션 AbortSignal 및 요청 세대 검사로 이전 사용자 응답을 반영하지 않습니다.
- 기존 로그인·프로필 API의 저장/전달 방식을 유지합니다. 공통 apiRequest에 토큰을 자동 주입하지 않고 각 보호 요청에서 확인된 세션을 명시적으로 전달합니다.

스크랩 Controller는 인증 상태·사용자 변경 시 교체·폐기하여 이전 목록과 공유 상태를 제거합니다. 보호 요청은 공통 AbortSignal과 연결합니다. Provider 자체로 전체 Routes를 재마운트하지 않아 같은 계정의 인증 재확인 중 작성·수정 입력은 유지합니다. 개발용 모집글 응답을 실제 스크랩 공유 상태에 관찰값으로 넣지 않습니다.

입력은 같은 계정의 인증·권한 오류 동안 유지합니다. 다른 계정으로 바꾸거나 명시적으로 로그아웃하면 이전 계정의 입력·개인 데이터도 폐기합니다. 개발 예시는 기존 환경·쿼리 조건을 유지하고 실제 실패를 예시 성공으로 바꾸지 않습니다. 작성 API는 기존 규칙대로 조회 예시 설정과 별개로 실제 API를 사용하며 이를 화면에 안내합니다.

## 검증

- `npm.cmd run build`, `npm.cmd run lint` 통과.
- `node scripts/check-auth-session.mjs` 16개: 기존 13개에 스크랩·지원자 관리의 공통 Bearer/사용자 조회 재사용, 인증 확인 전 차단·로그아웃 후 늦은 응답 폐기, 관리자 실제 role 재사용·일반 사용자 차단을 추가했습니다. 개인 화면 차단 검증에 내 스크랩·지원자 관리를 포함했습니다.
- 기존 모집·지원 회귀 9개 스크립트 131개, 스크랩 24개, 팀원 내보내기 13개, 관리자 17개 모두 통과했습니다. 인증 16개 포함 총 201개입니다. 스크립트 내부 실제 모드/예시 모드 분기를 사용하며 별도 `--mock` CLI 옵션은 없습니다.
- 검증은 fetch 가로채기·세션 상태 제어·정적 React 렌더입니다. 실제 서버를 시작하거나 JWT·DB·CORS·학교 이메일·브라우저 통합을 검증하지 않았으므로 통합 성공으로 기록하지 않습니다.
- `git diff --check` 및 새 파일 공백·충돌 표시 검사 수행.

실제 통합 확인 때는 API 주소와 CORS, 백엔드·DB·Redis 및 기존 테스트 계정을 준비하고 조회 예시 모드를 끈 뒤 확인해야 합니다. 비밀번호·토큰·개인 데이터는 문서나 로그에 붙이지 않습니다.

- 실서버 준비: 실제 VITE_API_BASE_URL, 프론트 접속 origin에 대한 CORS, 기존 백엔드·MySQL·Redis 구동 상태를 확인해야 합니다. 이번 작업에서 서버·DB·계정은 변경하지 않았습니다.
- 기존 학교 인증 완료 팀장/지원자 두 계정과 모집 중 역할·PENDING/ACCEPTED 지원 데이터가 필요합니다. 비로그인 공개 조회 → 로그인 개인화 → 작성/수정/지원 → 마감/연락처 → 개인 목록/나가기 → 스크랩 → 지원자 수락/내보내기 순서로 확인합니다.
- 로그아웃·계정 전환·401/403·네트워크 중단·응답 유실 및 재조회 실패를 실제 브라우저에서 추가 확인해야 합니다. 이번 재개 작업에서는 실서버·브라우저·개발 예시 수동 검증을 수행하지 않았습니다.
