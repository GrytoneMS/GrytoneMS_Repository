# 천안·아산 대학생 팀원 모집 서비스

천안·아산권 대학생이 학교 경계를 넘어 공모전·대회·단기 프로젝트 팀원을 구하는 웹 서비스입니다.
팀장이 역할과 조건을 올리면, 학교 인증을 마친 학생이 역할에 지원하고, 팀장이 함께할 사람을 고릅니다.

**핵심 흐름:** 모집글 등록 → 역할 골라 지원 → 팀장 수락 → 연락 수단 공개 → 팀 구성 완료

## 차별점

- 천안·아산 9개 대학 **학교 인증**
- **역할 단위** 지원과 팀장 선택
- **수락된 지원자에게만** 연락 수단 공개

## 기술 스택

| 영역 | 스택 |
| --- | --- |
| 프론트엔드 | React (반응형 웹) |
| 백엔드 | Spring Boot (Java) |
| DB | MySQL 8.0 (InnoDB, utf8mb4) |
| 기타 | Redis (인증 코드), 오브젝트 스토리지 (업로드 파일) |

## 폴더 구조

```
.
├── frontend/   # React 웹
├── backend/    # API 서버
└── docs/       # 기획 문서 (PRD, 기능 명세서, DB 설계서)
```

## 1차 개발 범위

기능 명세서의 MVP 기능 중 아래는 1차에서 제외합니다.

- 카카오 로그인
- 모집글 임시저장
- 앱 푸시 알림 (웹 전환에 따라 알림함만 구현)

## 브랜치 규칙

| 브랜치 | 용도 |
| --- | --- |
| `main` | 시연용. 항상 실행되는 상태 유지 |
| `dev` | 작업을 합치는 브랜치 |
| `feature/front-기능ID` | 프론트 기능 개발 (예: `feature/front-LIST-01`) |
| `feature/back-기능ID` | 백엔드 기능 개발 (예: `feature/back-APPL-05`) |
| `fix/설명` | 버그 수정 |

- 작업은 `dev`에서 브랜치를 따서 진행하고, PR로 `dev`에 합칩니다.
- `main`에는 직접 푸시하지 않습니다.
- 기능 ID는 기능 명세서의 ID(AUTH, PROF, POST, LIST, APPL, NOTI, SCRP, SAFE, ADMN)를 그대로 씁니다.

## 커밋 메시지

```
타입: 내용 (기능ID)
```

| 타입 | 의미 |
| --- | --- |
| `feat` | 새 기능 |
| `fix` | 버그 수정 |
| `refactor` | 동작 변화 없는 코드 정리 |
| `style` | 화면 스타일, 코드 포맷 |
| `docs` | 문서 |
| `chore` | 설정, 패키지 등 기타 |

예: `feat: 모집글 목록 조회 API (LIST-01)`

## 실행 방법

> 프로젝트 세팅 후 채워 주세요.

```bash
# frontend
cd frontend
npm install
npm run dev

# backend
cd backend
./gradlew bootRun
```

환경 변수는 `.env`에 두고 커밋하지 않습니다. 필요한 키 목록은 `.env.example`로 공유합니다.
